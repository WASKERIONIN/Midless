# Стена воды в v42 — разбор и исправление

Источник: `Midless-src.rar` и `Midless-Windows-x64-v42.zip` из релиза `Test`
(коммит `7307294` в `main`). Проверено 2026‑09‑08.

## Что происходит

Вода в генераторе ставится правилом (`server/src/world/worldgenerator.c`,
`ServerWorldGenerator_Generate`):

```c
} else if (map[i] == 0 && p.y < 48) {
    block = 5;                       // вода: "воздух" ниже уровня моря
```

`map[i]` приходит из `GetTerrainPoint()`:

* `0` — воздух (точка выше поверхности рельефа);
* `1` — грунт;
* `2` — **пещера** (`a * b > 0.6f` по `caveNoise`), и в это значение
  превращается **любая** точка ниже поверхности, включая точки ниже уровня моря.

Клетки с `map == 2` пропускаются (`if (map[i] == 2) continue;`) и остаются
воздухом, а правило воды на них не смотрит. Итог: под уровнем моря рядом
с колонкой «воздух → вода» стоит колонка «пещера → сухой воздух». Вода
получает вертикальную грань в сухую пустоту — это и есть стена. Пещерный
шум трёхмерный, поэтому такие полости регулярно выходят на поверхность дна
и на берег (на скриншоте — гигантский «карман» пещеры, вскрытый рельефом).

Симуляция воды (`client/src/water.c`) тут ни при чём: она событийная и не
трогает сгенерированную воду, а «страж» `Water_SweepFloating` смотрит только
y 44…48 в радиусе 40 и будит по 24 клетки за раз. Даже если бы она сработала,
ваша вода не имеет объёма: стена просто размазалась бы тонкой плёнкой по всей
равнине.

## Доказательство

`build.sh` компилирует **ваш** `worldgenerator.c` без изменений (заглушены
только `MemAlloc`/файлы/лог) и сканирует 21×21 чанк вокруг спавна:

| сид | вода рядом с сухим воздухом | вода над воздухом | сухой воздух ниже y=48 |
|---|---|---|---|
| 1234 | 2540 | 2893 | 276 477 |
| 7 | 2569 | 3132 | 285 104 |
| 99991 | 1745 | 2795 | 253 782 |

Все 100 % сухих клеток ниже уровня моря помечены генератором как пещера
(`map == 2`) — отдельная проверка, ноль исключений.

После патча — 0 / 0 / 0 на всех трёх сидах.

Срез `seed 1234, z=-157, x=-40..10` (`~` вода, `.` воздух, `#` камень, `s` песок):

```
до:                                             после:
y=47 ~~~~~~~~~~~~~~~~~~~~~~~....~~~~~~~~~~~     y=47 ~~~~~~~~~~~~~~~~~~~~~~~ss#s~~~~~~~~~~~
y=45 ~~~~~~~~~~~~~~~~~~~~~~.......~~~~~~~ss     y=45 ~~~~~~~~~~~~~~~~~~~~~~s####Ss~~~~~~~ss
y=43 ~~~~~~~~~~~~~~~~~~~~~..........SSSSS##     y=43 ~~~~~~~~~~~~~~~~~~~~~s#######SSSSSSS##
y=40 ~ssSSS##SSs~~~~~~~~~...........#######     y=40 ~ssSSS##SSs~~~~~~~~~S#################
y=36 #############SssssS##.......##########     y=36 #############SssssS###################
```

## Почему README v42 говорит «исправлено», а стена на месте

Дизассемблировал `game.exe` из v42 (символы не вырезаны): `GetTerrainPoint`
там **байт‑в‑байт по логике совпадает с исходником из rar** — проверка
`p.y >= 16`, затем безусловный пещерный тест `a*b > 0.6`, никакого сравнения
с 48 перед ним нет. Константа 48 встречается только в `ServerWorldGenerator_Generate`
(правило воды/пляжа). То есть описанный в README фикс в бинарник v42 не попал —
скорее всего собрано не из той копии дерева.

## Патч

`worldgenerator-no-caves-below-sea.patch` — одна содержательная строка:

```c
if (p.y < SEA_LEVEL) return 1;   // в GetTerrainPoint, перед пещерным шумом
```

Ниже уровня моря пещеры не прорезаются (как в ваниль‑Minecraft: под уровнем
моря либо твёрдое, либо вода). Плюс `#define SEA_LEVEL 48` вместо трёх
магических 48. Затрагивает только новый рельеф: после сборки —
**Regenerate World** (папка `world` удаляется целиком) или **New World**.

Побочный эффект: под океаном больше нет подводных пещер. Если они нужны —
вариант «пещеры под морем заливать водой» (в `Generate`: `map[i]==2 && p.y<48
→ block = 5`) тоже убирает стену, но даёт затопленные тоннели, выходящие в сушу
по берегу; там понадобится проверка, что полость не сообщается с воздухом.

## Что ещё заметил по воде (не чинил)

* `Packet_HandleSetBlock` на клиенте → `World_SetBlock` → `Water_NotifyBlockChange`
  вызывается и для блоков, пришедших от сервера, но **до** того, как клиентская
  вода поставит свой блок, идёт `World_SetBlock` + `Network_Send(SetBlock)`.
  В мультиплеере вода симулируется у каждого клиента независимо и «дерётся»
  через сервер — источник рассинхрона. Правильное место симуляции — сервер.
* `Water_Set` не проверяет `isBlockDataReady` целевого чанка для клетки
  `below` при `bl == -1` (защищено), но `Sand_Step` вызывает `World_GetBlock`
  без `Water_AreaReady` — песок на границе прогрузки «видит» воздух в
  незагруженном чанке и проваливается.
* `WATER_MAX_ACTIVE 512` с заменой случайной ячейки при переполнении: при
  большом затоплении часть фронта молча теряется.

## Запуск

```sh
tools/v42-water-wall/build.sh /path/to/Midless-src            # ожидаемо: стены есть, код возврата 1
cd /path/to/Midless-src && patch -p1 < .../worldgenerator-no-caves-below-sea.patch
tools/v42-water-wall/build.sh /path/to/Midless-src            # ожидаемо: 0 / 0 / 0, код возврата 0
tools/v42-water-wall/slice 1234 -157 -40 10                   # срез для глаз
```

## Выбранный вариант исправления

Из трёх обсуждавшихся вариантов взят **(а) «ниже уровня моря пещер нет»**:

* это ровно то поведение, которое обещано в README v42 и которое есть в ванильном
  Minecraft (ниже уровня моря либо вода, либо твёрдое); одна строка, детерминированно,
  без обхода соседних чанков;
* (б) «затопленные пещеры» требует анализа связности с океаном на границах чанков
  (иначе прибрежные тоннели превращаются в те же дыры, только с водой в потолке);
* (в) серверная симуляция воды — отдельная большая задача, к стене отношения не имеет:
  стена рождается в генераторе, а не в симуляции.

Побочный эффект: подводных пещер больше не будет (пещеры выше y=48 не тронуты).

## Готовые бинарники: `release/Midless-Windows-x64-v42.1.zip`

Это релизные `game.exe` / `server.exe` **v42 с бинарным патчем** той же самой правки
(`binpatch/patch.py`), плюс нетронутые `textures/`, `ReShade-optional/`, `README.txt`
и новый `README-v42.1-water-fix.txt`. Контрольные суммы — `release/SHA256SUMS`.

Почему патчился бинарник, а не пересобирался exe: исходники в `Midless-src.rar` — не
ровно то, из чего собран v42 (в exe есть `/giveme`, `/where`, история чата, камень в руке
по умолчанию, `X: … PING`; в rar — нет). Пересборка из rar дала бы «v42 минус эти
функции». Бинарный патч меняет 36 байт в каждом exe и ничего больше:

```
GetTerrainPoint+0xEF:  jmp cave ; nop4          (было: movss xmm8,[1.5f] — вынесено в cave)
cave (хвост .text):    comiss xmm6,[48.0f]      ; xmm6 = p.y
                       jb  GetTerrainPoint+0x166 ; y < 48 -> mov eax,1 -> return 1
                       movss xmm8,[1.5f]
                       jmp GetTerrainPoint+0xF8
```

Плюс `.text.VirtualSize` расширен до `SizeOfRawData` и пересчитан `CheckSum`.
Патч ставится только если все ожидаемые байты на месте (assert'ы в `patch.py`).

### Как проверено без Windows

`binpatch/emu.py` исполняет генератор **прямо из exe** (Unicorn, x86-64), подменяя
десять импортов CRT (`rand/srand/malloc/…`), и считает те же три метрики:

| exe | сид, чанки | вода | вода рядом с сухим воздухом | вода над воздухом | сухой воздух < 48 |
|---|---|---|---|---|---|
| v42 оригинал | 1234, x −4..1, z −11..−9 | 28 001 | **184** | 105 | 7 885 |
| v42.1 game.exe | то же | 28 001 | 0 | 0 | 0 |
| v42.1 server.exe | то же | 28 001 | 0 | 0 | 0 |
| v42 оригинал | 7, x 6..8, z 7 | 9 318 | **104** | — | — |
| v42.1 (оба) | то же | 9 318 | 0 | 0 | 0 |
| v42 оригинал | 99991, x −7..−6, z 8 | 3 634 | **51** | — | — |
| v42.1 (оба) | то же | 3 634 | 0 | 0 | 0 |

(числа «оригинала» — нативный прогон `worldgenerator.c` из rar через `dumpchunk.c`;
эмуляция оригинального exe даёт байт-в-байт те же чанки, что и rar — это заодно
подтверждает, что генератор в rar == генератор в v42).

`binpatch/compare_native.py` сравнивает чанки из пропатченного exe с нативной сборкой
`worldgenerator.c` + C-патч: **identical=True** на всех проверенных чанках трёх сидов.
Точечно: 12 пещерных клеток ниже моря → оригинал `2`, патч `1`; пещеры выше моря
(y 58..65) → `2` в обоих; поверхностный воздух → `0` в обоих.

Полный прогон: `binpatch/verify.sh <папка с оригинальными exe v42> <Midless-src>`
(нужен `pip install unicorn`).

### Что сделать пользователю

1. Распаковать `release/Midless-Windows-x64-v42.1.zip` поверх v42 (или отдельно).
2. Запустить, **New World** (главное меню) или **Regenerate World** (пауза) —
   старая папка `world` (включая `seed.dat`) удаляется, мир генерируется заново.
   Старые сохранения с готовой стеной не чинятся — рельеф уже записан в `.dat`.

## Кросс-сборка из исходников без mingw: `crossbuild/build_windows.sh`

Если понадобится собрать exe из исходников на Linux без установленного
`x86_64-w64-mingw32-gcc`: скрипт скачивает `zig` (pip-пакет `ziglang`) и использует
`zig cc -target x86_64-windows-gnu` как замену mingw — с теми же флагами и списком
файлов, что в `tools/midless_build.sh` и `tools/build_raylib.sh` из rar (raylib 4.5.0 +
`rcore_patch.py`). Единственная правка исходников — `crossbuild/enet-clock_gettime-newer-mingw.patch`:
новые заголовки mingw-w64 сами определяют `clock_gettime`, а `enet.h` определяет его
ещё раз (ошибка компиляции; в старом mingw пользователя такого нет).

Проверено: `server.exe` 1.27 МБ и `game.exe` 2.37 МБ линкуются (PE64, GUI subsystem);
запустить их здесь негде (нет Windows/wine), поэтому в релиз они **не** положены —
в релизе бинарно пропатченные оригиналы v42.
